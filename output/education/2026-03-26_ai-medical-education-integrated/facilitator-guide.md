## 設計上のポイント

### 統合の設計思想
1. **3セッション分を「対立構造」で統合**: 「AIは強力」（Mount Sinai, BJC, IME）vs「AIには罠がある」（PNAS, Frontiers, JMIR）の緊張関係を軸にした
2. **「使うかどうか」から「どう教育に組み込むか」への移行**: IME 2026の80%データを冒頭に置くことで、「使わない」という選択肢を最初から外し、「どう使うか」の議論に集中させる
3. **PNAS研究の追加による深化**: 3/25版では「AIを使うとバイアスが増幅される」は臨床データのみだったが、PNAS研究により「AIそのものにバイアスがある」という構造的問題として位置づけ直した

### 30分→45分の拡張設計
- 追加15分の配分: IME導入データ（+2分）、BJC臨床実装（+2分）、PNAS詳細（+3分）、ハンズオン拡張（+1分）、ディスカッション拡張（+2分）、振り返り拡張（+5分）
- ハンズオンを中盤に維持（「体験→理論」の順序は変えない）
- 振り返りを5分に拡張し、選択式アクションで個別化

### なぜこの順番か
1. **衝撃（IME 80%）→ 進化の全体像 → 実装事例 → 限界発見 → 対策 → 体験 → 構造的理解 → 統合判断** の流れ
2. 3/25版の「衝撃→体験→理論」を維持しつつ、前段に「進化の全体像」と「実装事例」を追加し、AIの力を十分に理解した上で限界を論じる構成
3. PNAS研究を「バイアスセクション」に統合し、体験前に「何を見るべきか」の視点を与えてからハンズオンに入る

### 時間調整の優先度（カットする場合）
1. **最後にカット:** Slide 5（BJC事例）→ 口頭1分に圧縮可能
2. **次にカット:** Slide 10の複雑性ステージ → 「Stage 1は得意、Stage 2は苦手」と一言に
3. **絶対にカットしない:** Slide 1（導入データ）、Slide 7（PNAS）、Slide 9（ハンズオン）、Slide 13（振り返り）

| バイアス | 人間 | AI | 対策 |

| **不作為バイアス** | あり | **人間より強い** | AIの「何もしない」推奨を疑う |
| **フレーミング効果** | あり | **顕著** | 同じ質問を言い換えて再度聞く |

### AIの3つの使い方

```
1. Framework Coach    → 「見落としている鑑別は？」
2. Socratic Guide     → 「なぜその診断だと思う？」
3. Red Team Partner   → 「間違っていたら最も危険な見逃しは？」
```

> **原則:** AIに「答え」を聞かない。「問い」を立てさせる。

### 使い分け早見表

```
推奨:     OSCE練習 / 鑑別チェック / EBM文献要約
非推奨:   複雑症例の答え合わせ / 共感練習
要注意:   終末期ケア判断（不作為バイアスに注意）
時期尚早: 多疾患シミュレーション
```

### 複雑性ステージ早見表

```
Stage 1（安定）    → AIが得意   → 単一疾患、OSCE練習に使える
Stage 2（創発）    → AIが苦手   → 多疾患、心理社会的文脈は人間の指導が必要
                     + 不作為バイアスの影響が拡大
```

### 明日からのアクション（1つ選んで実行）

**選択肢A: ソクラテス的ガイドを試す**
> 「45歳女性、倦怠感と微熱。私は甲状腺機能低下を疑っています。
> この患者で私が見落としている可能性のある鑑別診断を、
> 最も危険なものから順に3つ挙げて、それぞれなぜ考えるべきか教えてください。」

**選択肢B: Red Teamを試す**
> 「私の診断が間違っているとしたら、最も危険な見逃しは何ですか？
> 私の推論のどこに認知バイアスがかかっている可能性がありますか？」

**選択肢C: フレーミング効果を検証する**
> 同じ症例を2通りの聞き方でAIに質問し、答えが変わるかどうか確認する。
